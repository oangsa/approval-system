# Issue #11 API contract

All responses are direct DTOs, private and no-store; authentication and centralized errors remain in force. Export `dashboardSchema` / `DashboardDTO`; `reportSearchSchema` / `ReportSearch`, `reportDimensionSchema` / `ReportDimension`, `reportAggregateRowSchema` / `ReportAggregateRow` from shared contracts.

`GET /api/v1/dashboard`: strict role-corresponding DTO union for the seven nonempty combinations of Requester, Reviewer and Administrator. Every variant contains `roleContext` and `generatedAt`. Requester section has `summary` fields `ownRequests`, `pendingRequests`, `returnedRequests`, `approvedRequests`, `rejectedRequests` and `recentRequests: RequestSummary[]`. Reviewer section has `summary` fields `pendingReviews`, `overdueTasks`, `pendingTasks: ApprovalTask[]`, and `recentDecisions` with only own decision `id`, `decision`, `decidedAt`, `taskId`, `requestId`, `cycleId`, `revisionId`. Administrator `administration` contains `statusCounts: ReportAggregateRow[]`, configuration counts of enabled published types, active policy versions and active assignment rules, and escalation counts `actionableTasks`, `overdueTasks`. Shared `summary` includes exactly fields authorized by roles. Lists cap at five; ties use stable IDs. No delegation/notification placeholders or private admin drill-downs.

`POST /api/v1/reports/requests/search`: strict existing search envelope, dimension default STATUS; pageNumber default 1, maximum 10000; pageSize default 20, maximum 100; at most 20 conditions. `status` supports EQUAL/NOTEQUAL with enum; `typeId` and `departmentId` EQUAL UUID; `departmentId` ISNULL/ISNOTNULL carries no value; `createdAt` GREATEROREQUAL/LESSER accepts UTC instant. Reject reversed date ranges with 422. Optional `searchTerm` is `{name: 'label', value: bounded string}`. `orderBy` permits key, label or count ascending/descending with deterministic tie ordering. Unknown fields/operators and malformed values return 422. Response is direct `ReportAggregateRow[]` with exposed `X-Pagination` measuring positive aggregate groups, including truthful zero totals. Dimension STATUS or OUTCOME keys are enum values; TYPE key is UUID and label type code; DEPARTMENT key is UUID and label department name, or key `UNASSIGNED` and label `No department`. Each row has dimension, key, label, count. Filter and count operate within authorized scope and one repeatable snapshot.

`GET /api/v1/requests/:id/timeline` retains existing authorized bounded history contract, including its current scope restrictions. No new endpoint, PDF/CSV, charts or permissions are included.

Exact field rules: roles use `REQUESTER`, `REVIEWER`, `ADMINISTRATOR`; `roleContext` is nonempty and unique. `summary` contains only the numeric fields granted by requester/reviewer roles and is absent for administrator-only viewers. `pendingTasks` and `recentDecisions` are top-level reviewer fields, not summary properties. `administration.configuration` is `{ enabledPublishedTypes, activePolicyVersions, activeAssignmentRules }`; `administration.escalation` is `{ actionableTasks, overdueTasks }`. Counts are nonnegative integers; returned aggregate rows have positive integer counts. Recent decision identifiers are non-null UUIDs, `decision` uses the existing decision enum, and `decidedAt`/`generatedAt` are UTC instants. `orderBy` defaults to `key asc`; label search is trimmed, nonempty and at most 200 characters. Existing request/task summary nullability remains unchanged.
