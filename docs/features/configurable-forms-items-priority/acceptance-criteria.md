# Numbered acceptance criteria — v1

1. CF-AC-01 (AC-033): Authenticated type lookup/search exposes active published metadata; authorized pinned-version GET works without draft leakage. Admin `POST /api/v1/admin/request-types` creates draft; `PATCH /:id/draft` requires `expectedVersion`; `POST /:id/draft` branches latest immutable publication.
2. CF-AC-02 (AC-033): `POST /api/v1/admin/request-types/:id/publish` requires `expectedVersion` and `Idempotency-Key`, returns `201 PublishedRequestType`; concurrent or stale publish cannot create duplicate version. Enable/disable take `expectedVersion`, preserve history, and allow legitimate returned pinned edits/resubmission.
3. CF-AC-03 (AC-033, BR-014, BR-016): Field vocabulary is `TEXT`/`TEXTAREA`/`DECIMAL`/`DATE`/`SELECT`/`BOOLEAN` with localized labels, typed options/bounds, and unique keys. Reject unknown/duplicate references, incompatible operator/value, self-reference, and cycles across visibility/requiredness before publish.
4. CF-AC-04 (AC-033, BR-015): Conditions support `EQ`/`NE`/`GT`/`GTE`/`LT`/`LTE`/`IN`/`PRESENT` and bounded `all`/`any`; if both groups exist combine results with AND. Empty provided groups are invalid, missing group contributes true, boolean `false` is `PRESENT`.
5. CF-AC-05 (AC-033, BR-017, BR-018): Evaluate dependency graph in order. Hidden field is unset for downstream evaluation and never required; visible field required when base `required` or `requiredWhen` is true. Browser omits hidden keys; direct draft/submit hidden-key input returns `422 FORM_FIELD_NOT_APPLICABLE`.
6. CF-AC-06 (AC-033, BR-019, BR-020, BR-021): Server validates stored published definition at runtime in addition to static Zod. New first submission checks active version (`409 FORM_DEFINITION_CHANGED` if stale); submitted/returned versions never silently migrate.
7. CF-AC-07 (AC-033, BR-022): Admin field list supports add/edit/remove/reorder, constrained rule editing, live preview, and immutable publish confirmation; non-admin mutation is denied and `422`/`409` feedback preserves editable draft.
8. CF-AC-08 (AC-024, BR-031): Line-item-enabled types accept `{description, quantity, unitAmount}` only as editable authority; server generates IDs, requires positive quantities/nonnegative valid unit amounts, computes exact per-row/total decimal strings, and rejects attempted client total override.
9. CF-AC-09 (AC-024, BR-031): Monetary types without items may use validated `monetaryAmount`; competing `monetaryAmount` and `lineItems` cannot supply two authorities. Nonmonetary types exclude monetary input; no float arithmetic or currency conversion.
10. CF-AC-10 (AC-034, BR-032): Priority `LOW`/`MEDIUM`/`HIGH`/`URGENT` round-trips across API and wizard/details; unsupported values yield `422`. Priority does not grant authorization or arbitrarily override routing.
11. CF-AC-11 (AC-024, AC-033, AC-034, BR-070): Wizard renders dynamic conditions/labels with English fallback, item row errors, and server-confirmed totals, is read-only after submit, and supports busy/stale/configuration states. Evaluator, contract, real-PostgreSQL publication, and admin-to-requester E2E execute with recorded evidence.
12. CF-AC-12: Teammate reviews bounded implementation; feature PR targets `sprint-2-staging`, followed by reviewed promotion to `dev` then release-reviewed `main`. Applicable typecheck, lint, build, and planned tests run; actual commit/environment/results and any failures/skips are recorded.
