# Workflow and Approval System

CPE334 Theme 5 application: React Router 7 Framework Mode with public SSR, Tailwind/shadcn, Elysia on Node.js, PostgreSQL/Drizzle, and shared Zod contracts. Authentication and role access, request submission, and a scoped request list and detail are implemented; other business features remain with their owning issues.

## Install and run

Use **Node.js 24+ and npm 11+**. All workspace management, scripts, tests, builds, CI, and containers use npm/Node.js. Docker Compose v2 is needed for local databases.

```sh
npm install
cp apps/api/.env.example apps/api/.env
cp apps/web/.env.example apps/web/.env
```

Choose a local password in the API `.env` and use the same URL-encoded password in `DATABASE_URL`. The development database is `workflow_dev`. Do not commit local environment files. Frontend and backend load their own environments; there is no shared root `.env`. `VITE_` variables are public and must contain no secrets.

```sh
npm run db:up
npm run db:check
npm run dev
```

The root dev supervisor starts both applications and stops their process groups together (Linux/macOS). Web: http://localhost:5173. API: http://127.0.0.1:3001/health. The health endpoint is liveness-only; use `db:check` to verify a real database connection. The frontend is served by React Router on Node.js; Elysia uses its official Node adapter.

Keep **one root `package-lock.json`** generated by `npm install` and commit it before using `npm ci`, CI, or Docker builds. No per-package or Bun lockfiles are used.

### Disposable PostgreSQL tests

```sh
cp apps/api/.env.test.example apps/api/.env.test
# Choose a separate test password and update TEST_DATABASE_URL to match.
npm run db:test:up
npm run db:test:migrate
npm run db:test:seed
npm run test:integration
npm run db:test:down
```

`apps/api/.env.test` is optional and ignored by Git. CI can inject the same variables without creating a file. The dedicated test service uses `workflow_test` on loopback port 55432 and tmpfs storage; stopping/removing the container discards its data. It has no development volume. Never supply production credentials.

The reusable guard requires `NODE_ENV=test`, explicit `TEST_DATABASE_URL`, PostgreSQL protocol, a loopback host, and the exact name `workflow_test`. Unset `PGPORT`; put the port in `TEST_DATABASE_URL` so driver defaults cannot change the verified target. Encoded spellings of the test database name are rejected because postgres.js treats the path literally. The guard also rejects query/fragment overrides, malformed URLs, remote targets, ambiguous development baselines, and targets equal to `DATABASE_URL` after normalizing host aliases, default ports, and encoded database names. Integration connections use `TEST_DATABASE_URL` exclusively. No environment variable silently falls back to development.

`npm run db:test:migrate` uses a separate guarded Drizzle configuration and the same test environment loader. Development migration commands also invoke the guard in test mode. No reset/cleanup command is introduced; future destructive tools must call the guard before opening a connection. Reviewed migrations create the identity, role, department, and session tables; `npm run db:test:seed` applies the idempotent synthetic identity fixtures.

If PostgreSQL is unavailable, the suite fails with setup instructions rather than reporting success. Ordinary tests do not load `.env` or `.env.test` and need no external database.

### Browser tests

```sh
npm run db:test:up
npm run db:test:migrate
npm run db:test:seed
npm run test:e2e:install
npm run test:e2e
```

Playwright builds and starts the SSR web server and the Node API automatically, refuses to reuse manually started servers, and stops them afterward. Dedicated defaults are web `127.0.0.1:14173` and API `127.0.0.1:14174`. Override `E2E_WEB_PORT`/`E2E_API_PORT` or `E2E_WEB_URL`/`E2E_API_URL` with distinct loopback HTTP origins. The suite needs the disposable `workflow_test` database migrated and seeded first (`TEST_DATABASE_URL`, default `postgresql://127.0.0.1:55432/workflow_test`). The Playwright web servers build both applications before starting them, baking the API origin into the client bundle automatically.

The suite checks server-rendered HTML, accessible content/title, real React hydration commits without browser errors, desktop/mobile overflow, and API health through its real listener. Authentication journeys cover real login, wrong credentials, refresh-cookie bootstrap, logout and re-authentication, account switching without stale identity, drawer focus management, and public SSR privacy. It observes React's DevTools commit hook instead of adding testing markers or artificial controls to the application.

Failure screenshots, retained traces, and HTML reports are under `artifacts/playwright/`; coverage is under `artifacts/coverage/`. Generated artifacts are Git-ignored. GitHub Actions provisions disposable PostgreSQL, runs checks/builds/tests, and builds both production API and web images from the repository root. It builds and uses the preinstalled-browser image defined in `.github/ci/playwright.Dockerfile` to run the browser suite, then uploads diagnostics. It does not push images or deploy. See [Lab 5 CI quality gates](docs/labs/lab-05/ci-quality-gates.md) for the required check and C-01/C-02 evidence procedures.

## Structure and architecture

```text
apps/web/
  app/routes/                     Thin route modules: home, login, protected layout, dashboard, settings, unauthorized
  app/modules/auth/               Session provider and accessible login form
  app/modules/shell/              App shell, role-filtered navigation, protected layout
  app/api/http.ts                 Authenticated transport: in-memory token, single-flight refresh, frozen error envelope
  app/api/tokenStore.ts           Memory-only access token with identity generations
  app/services/                   authService login/bootstrap/me/logout orchestration
  app/components/ui/              Future raw shadcn primitives
  app/lib/utils.ts                shadcn cn utility
  components.json                 Manual shadcn initialization, aliases, theme tokens
  tests/{helpers,unit,components}/ Testing Library and MSW suites for transport, login, shell
  vitest.config.ts                jsdom project, separate from SSR/build configuration
apps/api/
  src/index.ts                    Composition root and Node listener
  src/Domains/                    Identity model, ports, authorization policy, domain errors
  src/Applications/               Login, refresh, current-user, logout, logout-all use cases
  src/Presentations/              Application factory, auth routes, auth guards, CORS, safe errors
  src/Infrastructures/            Validated environment, Drizzle, database target guard
    Database/schema.ts            Identity, role, department, and session tables
    Database/migrations/          Reviewed migration SQL
    Security/                     Argon2id hashing, JWT signing, refresh tokens, login throttle
  tests/{helpers,unit,integration,postgres}/
  vitest.config.ts                Listener-free ordinary tests
  vitest.postgres.config.ts       Explicit guarded external integration tests
packages/contracts/
  src/index.ts                    Health, authentication, and error schemas with inferred types
  tests/                          Schema, exports, and type assertions
vitest.config.ts                  Ordinary projects and coverage
playwright.config.ts              Chromium, managed SSR/API servers, disposable PostgreSQL
e2e/                              Smoke and authentication browser journeys
.github/workflows/ci.yml           Verification only
```

Domain and Application layers exist for the identity feature. Dependency direction is Presentation → Application → Domain; Infrastructure implements inner interfaces. The composition root supplies Elysia's Node adapter. `createApplication()` instantiates the same HTTP routes/error handling without loading environment files or binding a port. Database connections are explicitly constructed and closed.

Feature modules call services; services orchestrate resource API methods, which use `http`. Validate returned `unknown` data with shared Zod schemas. The contracts workspace depends only on Zod and exposes TypeScript source for Vite/tsx, with compiled declarations available from its build. The API bundler includes workspace contracts and leaves runtime libraries external. Raw shadcn components remain independent of feature logic; add only needed primitives from `apps/web`.

`ssr: true` preserves public SSR and hydrated SPA navigation. Private routes bootstrap identity in the client after hydration through the session provider, so no user data enters public SSR HTML; server loaders must never serialize credentials or identity. Follow [React Router client-data guidance](https://reactrouter.com/how-to/client-data). Authentication is email plus application password: a short-lived access JWT is held in module memory only, and a seven-day rotating refresh token lives in an HttpOnly cookie scoped to `/api/v1/auth`. Authorization, session validity, and ownership are re-checked on every protected server request.

## Containers and references

```sh
docker build -f apps/api/Dockerfile -t workflow-api .
docker build -f apps/web/Dockerfile -t workflow-web .
```

Both images use Node.js and npm and run as the Node user. Pass API `DATABASE_URL` at runtime with a database hostname reachable from the container. Local environment files are excluded. PostgreSQL development data persists in a named volume; changing the initial password does not change an existing database user's password. Review schema changes and generated SQL together; do not replace migrations with schema push.

Architecture references: [frontend](https://github.com/oangsa/maintenance-tracking-system), [backend](https://github.com/oangsa/maintenance-tracking-system-api), and [TokTickIT testing](https://github.com/oangsa/TokTickIT). Testing adaptations and acceptance criteria are recorded in [testing notes](docs/testing.md), with actual command outcomes in [verification evidence](docs/testing-verification.md) and AI assistance disclosed in [ai_use.md](ai_use.md). No reference repository was modified.

Authentication allows only origins explicitly listed in `AUTH_ALLOWED_ORIGINS`; the example includes the built web server on port 3000 and Vite on port 5173. Login limits use the direct socket peer and ignore forwarding headers. Clients behind one reverse proxy or NAT share a source bucket. Per-user proxy trust and distributed limits require separate deployment work.

### Request submission (Issue #2)

`/requests/new` creates incomplete drafts and submits a validated immutable revision. The initial seed provides a General request type, trusted Operations department and one eligible reviewer. Configuration UI, decisions and full draft/resume lifecycle remain with their owning issues.

For local development, configure the ignored `apps/api/.env` from its safe example, then run `npm run db:up`, `npm run db:migrate`, `npm run db:seed`, and `npm run dev`. Development seeding only accepts loopback `workflow_dev` in development mode. Local accounts are `requester@example.test` and `reviewer@example.test`; their separate passwords come from `DEV_REQUESTER_PASSWORD` and `DEV_REVIEWER_PASSWORD` in that ignored file. Seeding is repeatable and does not reset existing accounts. Never copy real credentials into examples.

Tests use the separate ignored `apps/api/.env.test`: run `npm run db:test:up`, `NODE_ENV=test npm run db:test:migrate`, `NODE_ENV=test npm run db:test:seed`, then `NODE_ENV=test RUN_BUILT_HTTP_SMOKE=1 npm run test:integration` after building. Playwright loads the same guarded test connection and runs one worker locally and in CI to limit CPU and RAM usage. Development data is never a test fallback. The test database is disposable; immutable submitted test evidence is retained until its database/container is recreated.

Feature design, numbered acceptance criteria and test mapping: [request submission](docs/features/request-submission/sds.md). Actual local verification: [evidence](docs/features/request-submission/verification.md).
