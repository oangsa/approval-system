# Workflow and Approval System

CPE334 Theme 5 template: React Router 7 Framework Mode with public SSR, Tailwind/shadcn, Elysia on Node.js, PostgreSQL/Drizzle, and shared Zod contracts. No business features, authentication, tables, or sample data are implemented.

## Install and run

Use **Node.js 24+ and npm 11+**. All workspace management, scripts, tests, builds, CI, and containers use npm/Node.js. Docker Compose v2 is needed for local databases.

```sh
npm install
cp apps/api/.env.example apps/api/.env
cp apps/web/.env.example apps/web/.env
```

Choose a local password in the API `.env` and use the same URL-encoded password in `DATABASE_URL`. The development database is `workflow_dev`. Do not commit local environment files. Frontend and backend load their own environments; there is no shared root `.env`. `VITE_` variables are public and must contain no secrets.

```sh
npm run db:up
npm run db:check
npm run dev
```

The root dev supervisor starts both applications and stops their process groups together (Linux/macOS). Web: http://localhost:5173. API: http://127.0.0.1:3001/health. The health endpoint is liveness-only; use `db:check` to verify a real database connection. The frontend is served by React Router on Node.js; Elysia uses its official Node adapter.

Keep **one root `package-lock.json`** generated by `npm install` and commit it before using `npm ci`, CI, or Docker builds. No per-package or Bun lockfiles are used. Installation is currently blocked in the scaffold environment; see [verification evidence](docs/testing-verification.md).

## Development commands

GitHub Kanban setup, automatic status transitions, and manual recovery steps are documented in [Project automation](docs/project-automation.md).

| Command                             | Purpose                                                                  |
| ----------------------------------- | ------------------------------------------------------------------------ |
| `npm run dev`                       | Start both development servers with reload                               |
| `npm run typecheck`                 | Generate React Router types; check every workspace, test, and root tool  |
| `npm run lint`                      | Lint `.ts` and `.tsx` files, including Allman braces                     |
| `npm run format`                    | Fix lint style in `.ts` and `.tsx` files                                |
| `npm run build`                     | Build web SSR/client assets, API bundle, and contracts declarations      |
| `npm run check`                     | Typecheck, lint, ordinary tests, and builds                              |
| `npm run db:up` / `npm run db:down` | Start/stop development PostgreSQL; retain its named volume               |
| `npm run db:check`                  | Execute `SELECT 1` through Drizzle against the configured development DB |
| `npm run db:generate`               | Generate migrations after adding real, reviewed tables                   |
| `npm run db:migrate`                | Apply reviewed development migrations                                    |

After building, start applications in separate terminals:

```sh
npm run start --workspace @workflow/api
npm run start --workspace @workflow/web
```

The built web server defaults to port 3000. Configure `HOST`/`PORT` as needed. The Vite development proxy forwards `/api/*` to the API with the `/api` prefix removed. In production configure that forwarding in a reverse proxy; separate-origin hosting needs an explicit CORS allowlist when introduced.

## Testing commands

| Command                    | Scope and prerequisites                                              |
| -------------------------- | -------------------------------------------------------------------- |
| `npm test`                 | All ordinary Vitest projects; no database, browser, or HTTP listener |
| `npm run test:web`         | jsdom, Testing Library, jest-dom, and MSW                            |
| `npm run test:api`         | Environment/guard unit tests and Elysia `.handle()` tests            |
| `npm run test:contracts`   | Zod behavior, package exports, and inferred-type assertions          |
| `npm run test:coverage`    | Ordinary tests with V8 text, HTML, and LCOV reports                  |
| `npm run test:integration` | Explicit guarded real PostgreSQL integration suite                   |
| `npm run test:e2e:install` | Install Chromium and its host dependencies                           |
| `npm run test:e2e`         | Build applications, start isolated servers, and run Playwright       |

No control exists on the static starter page, so no artificial interaction was added. `@testing-library/user-event` is installed for future interactive components. MSW starts without default handlers and rejects unexpected HTTP requests; individual transport tests mock only the existing health endpoint. Test configuration is separate from the React Router build plugin and never enters production setup.

### Disposable PostgreSQL tests

```sh
cp apps/api/.env.test.example apps/api/.env.test
# Choose a separate test password and update TEST_DATABASE_URL to match.
npm run db:test:up
npm run test:integration
npm run db:test:down
```

`apps/api/.env.test` is optional and ignored by Git. CI can inject the same variables without creating a file. The dedicated test service uses `workflow_test` on loopback port 55432 and tmpfs storage; stopping/removing the container discards its data. It has no development volume. Never supply production credentials.

The reusable guard requires `NODE_ENV=test`, explicit `TEST_DATABASE_URL`, PostgreSQL protocol, a loopback host, and the exact name `workflow_test`. Unset `PGPORT`; put the port in `TEST_DATABASE_URL` so driver defaults cannot change the verified target. Encoded spellings of the test database name are rejected because postgres.js treats the path literally. The guard also rejects query/fragment overrides, malformed URLs, remote targets, ambiguous development baselines, and targets equal to `DATABASE_URL` after normalizing host aliases, default ports, and encoded database names. Integration connections use `TEST_DATABASE_URL` exclusively. No environment variable silently falls back to development.

`npm run db:test:migrate` uses a separate guarded Drizzle configuration and the same test environment loader. Development migration commands also invoke the guard in test mode. No reset/cleanup command is introduced; future destructive tools must call the guard before opening a connection. There are currently no migrations to apply. Integration tests issue only infrastructure queries and never create business tables.

If PostgreSQL is unavailable, the suite fails with setup instructions rather than reporting success. Ordinary tests do not load `.env` or `.env.test` and need no external database.

### Browser tests

```sh
npm run test:e2e:install
npm run test:e2e
```

Playwright builds and starts the SSR web server and the Node API automatically, refuses to reuse manually started servers, and stops them afterward. Dedicated defaults are web `127.0.0.1:14173` and API `127.0.0.1:14174`. Override `E2E_WEB_PORT`/`E2E_API_PORT` or `E2E_WEB_URL`/`E2E_API_URL` with distinct loopback HTTP origins. No database is needed for this liveness-only browser suite; the API receives an explicitly isolated, unreachable test URL rather than developer credentials.

The suite checks server-rendered HTML, accessible content/title, real React hydration commits without browser errors, desktop/mobile overflow, and API health through its real listener. It observes React's DevTools commit hook instead of adding testing markers or artificial controls to the application.

Failure screenshots, retained traces, and HTML reports are under `artifacts/playwright/`; coverage is under `artifacts/coverage/`. Generated artifacts are Git-ignored. GitHub Actions provisions disposable PostgreSQL, runs checks/builds/tests, installs Chromium, runs the browser suite, and uploads diagnostics. It performs no deployment.

## Structure and architecture

```text
apps/web/
  app/routes/                     Thin route modules; generic starter only
  app/modules/                    Future feature modules
  app/api/http.ts                  HTTP transport returning unknown data
  app/services/                   Future UI request orchestration
  app/components/ui/              Future raw shadcn primitives
  app/lib/utils.ts                shadcn cn utility
  components.json                 Manual shadcn initialization, aliases, theme tokens
  tests/{helpers,unit,components}/ Testing Library and MSW foundation
  vitest.config.ts                jsdom project, separate from SSR/build configuration
apps/api/
  src/index.ts                    Composition root and Node listener
  src/Presentations/              Application factory/class and safe HTTP errors
  src/Infrastructures/            Validated environment, Drizzle, database target guard
    Database/schema.ts            No tables
    Database/migrations/          Future reviewed migrations
  tests/{helpers,unit,integration,postgres}/
  vitest.config.ts                Listener-free ordinary tests
  vitest.postgres.config.ts       Explicit guarded external integration tests
packages/contracts/
  src/index.ts                    Health response schema and z.infer type only
  tests/                          Schema, exports, and type assertions
vitest.config.ts                  Ordinary projects and coverage
playwright.config.ts              Chromium and managed SSR/API servers
e2e/                              Infrastructure browser smoke tests
.github/workflows/ci.yml           Verification only
```

Add `Domains` and `Applications` only when real abstractions/use cases exist. Dependency direction is Presentation → Application → Domain; Infrastructure implements inner interfaces. The composition root supplies Elysia's Node adapter. `createApplication()` instantiates the same HTTP routes/error handling without loading environment files or binding a port. Database connections are explicitly constructed and closed.

Feature modules call services; services orchestrate resource API methods, which use `http`. Validate returned `unknown` data with shared Zod schemas. The contracts workspace depends only on Zod and exposes TypeScript source for Vite/tsx, with compiled declarations available from its build. The API bundler includes workspace contracts and leaves runtime libraries external. Raw shadcn components remain independent of feature logic; add only needed primitives from `apps/web`.

`ssr: true` preserves public SSR and hydrated SPA navigation. Future private routes should use `clientLoader`, `clientLoader.hydrate = true as const`, and `HydrateFallback`, with no sensitive data in server loaders or initial render. Follow [React Router client-data guidance](https://reactrouter.com/how-to/client-data). Future authentication remains email/application password, access JWT, and rotating refresh tokens in HttpOnly cookies with server-controlled authorization. No authentication or token storage is implemented.

## Containers and references

```sh
docker build -f apps/api/Dockerfile -t workflow-api .
docker build -f apps/web/Dockerfile -t workflow-web .
```

Both images use Node.js and npm and run as the Node user. Pass API `DATABASE_URL` at runtime with a database hostname reachable from the container. Local environment files are excluded. PostgreSQL development data persists in a named volume; changing the initial password does not change an existing database user's password. Review schema changes and generated SQL together; do not replace migrations with schema push.
